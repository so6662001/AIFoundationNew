D原型与方案的对应关系
DAG JSON 契约：编辑器「DAG JSON」弹窗输出与 schemas/dag.schema.json 同构；分支规则、审批人模型、for-each 字段与 docs/01 一致。
节点 SDK：注册中心「如何新增节点」展示 @AgentNode Java 写法（docs/02）；节点面板的 Java / Python 标记、Worker 离线态来自注册中心心跳。
解释器行为：监控页的重试次数、暂停处置（重试 / 跳过 / 终止）、审批 Signal、for-each 进度与 continue-as-new 均对应 docs/03 的 DagWorkflowImpl 设计。
企业差异走配置：企业配置页的 profile / 通道 / 身份源对应 docs/05 的 SPI 与 profiles、notification_channels、departments/users/roles 表。
三条铁律的可见体现：① Workflow 只编排——分支 / 赋值节点标注"Workflow 内纯函数"，任务节点标注队列与 Worker；② LLM 不决定走向——LLM 节点输出 Schema 禁止保留字，走向只在分支节点配置；③ 上下文只存引用——监控页输出中 ref://artifact/…（MinIO）与上下文大小 vs 软限进度条。
