# 前端画布方案（React + xyflow）

> 应用：`apps/web`。技术栈：React 18 + TypeScript + Vite + `@xyflow/react` v12 + Zustand + Ant Design 5 + `@rjsf/antd`（JSON Schema 表单）+ Monaco（JSON 视图）+ `dag-core-ts`（校验 / 规则 / 模板，与 Python 版共享测试向量）。

---

## 1. 页面与信息架构

```
/flows                         流程列表（搜索、标签、最近运行状态、当前发布版本）
/flows/:id/edit                画布编辑器（默认打开草稿；只读查看历史版本）
/flows/:id/versions            版本管理（列表、Diff、发布、回滚）
/flows/:id/runs                运行列表（状态、耗时、触发人、版本）
/runs/:runId                   运行监控（画布只读 + 节点状态着色 + 右侧监控面板）
/approvals                     我的待审批
/registry                      节点注册中心（节点类型、Schema、在线 Worker、语言）
/metrics                       流程度量看板（节点耗时 P50/P95、失败率、审批时长）
/settings/profiles             企业配置：ERP 数据源 profile（直连库 / 接口 / 文件映射向导）、LLM profile、对象存储
/settings/notifications        通知通道（企业微信默认；钉钉 / 飞书 / 邮件 / Webhook）与告警路由
/settings/identity             身份源（OIDC）、组织架构同步状态、角色映射
```

登录走 OIDC（Keycloak / 企业 IdP），前端只持有 access token；组织架构（部门树 / 用户 / 角色）通过 `/identity/*` 接口供审批人选择器使用。

## 3. 自定义节点组件

| 组件 | 对应 `kind` | 视觉 / 交互要点 |
|---|---|---|
| `StartNode` / `EndNode` | start / end | 圆形；`end` 显示 `status` 标记（success 绿 / failed 红） |
| `TaskNode` | task | 卡片：图标 + 名称 + `nodeType` 小字 + 输出键 `→ docs`；角标：重试次数、断点（红点）、Worker 离线（灰）；运行态叠加状态色与耗时 |
| `BranchNode` | branch | 菱形头 + 右侧按 `cases[]` 动态渲染多个 `sourceHandle`（`big` / `small` / `default`），每个 handle 旁显示 label；运行态高亮命中的 case |
| `ApprovalNode` | approval | 卡片 + 三个 handle：`approved` / `rejected` / `timeout`；运行态显示"等待 xxx 审批 · 已等待 2h" |
| `SubflowNode` | subflow | 卡片 + 展开按钮（跳转子流程 / 运行态下钻子 run） |
| `AssignNode` | assign | 简洁卡片，列出 `target = value` |
| `ForEachNode` | foreach | **容器卡片**：头部显示 `items` 表达式、并发数、失败策略；内部嵌一张循环体卡片（单任务或子流程引用，可点击编辑/跳转）；运行态显示进度环 `18/20`、成功/失败计数，点击展开 item 列表（虚拟滚动）并可下钻单个 item 的日志/IO |
| `ParallelNode` / `JoinNode` | parallel / join | 竖条形 |
| `DagEdge` | edge | `smoothstep`；label；分支边显示 case label；运行态：已走过的边加粗高亮，未走过的边淡化 |

节点数据 `data` 结构直接持有 DAG 节点对象（除 `position`），`toDag/fromDag` 只做壳转换，避免双份模型。

## 4. 状态管理（Zustand）

```ts
interface EditorStore {
  flow: FlowMeta; nodes: Node<DagNodeData>[]; edges: Edge<DagEdgeData>[];
  selectedId?: string; issues: Issue[]; dirty: boolean;
  nodeTypes: NodeSpec[];                 // 来自 /registry/node-types
  actions: { addNode(spec|kind, position); updateNode(id, patch); connect(conn); remove(ids); validate(); save(); publish(); }
}
interface RunStore {
  run: RunMeta; nodeRuns: Record<string, NodeRunState>; events: RunEvent[]; context: object;
  connect(runId): void;  // SSE 订阅 + 断线重连（携带 since=lastEventId），首次加载走 GET 快照
  approve(nodeId, decision, form); manualAction(nodeId, action); toggleBreakpoint(nodeId);
}
```

## 5. 拖拽 / 连线规则（`isValidConnection`）

- `start` 只能有出边，`end` 只能有入边。
- `branch` 每个 `case` handle 与 `default` handle 各只允许一条出边；`approval` 的三个 handle 同理。
- 禁止自环；连线时用 `dag-core-ts.wouldCreateCycle(edges, newEdge)` 即时阻止成环并 toast 提示。
- 普通节点入边不限（join 语义 = all）。
- 从节点面板拖入 `task` 时按 `NodeSpec` 预填 `inputs`（required 字段留空模板）、`config`（默认值）、`retryPolicy`、`timeouts`、`outputKey`（`nodeType` 名 snake_case，冲突自动加后缀）。

## 6. 属性面板（Inspector）

| Tab | 内容 | 实现 |
|---|---|---|
| 基本 | `name` / `description` / `outputKey` / `breakpoint` | 表单 |
| 输入映射 | 按 `inputSchema.properties` 逐字段：文本框 + **变量选择器**（下拉列出 `input.*`、拓扑前驱节点的 `outputSchema` 字段、`run.*`；插入 `{{...}}`）；单占位符保留类型的提示 | 自研 `TemplateInput` |
| 配置 | `configSchema` + `uiSchema` → `@rjsf/antd` 自动表单 | rjsf |
| 分支规则（branch） | 规则构建器：`all/any/not` 分组 + `字段选择器 / 运算符 / 值(常量或变量)`；高级模式切换 `expr`；"用当前上下文测试"按钮（用历史 run 的 context 试算，纯前端） | 自研 `RuleBuilder`（复用 dag-core-ts 求值器） |
| 审批（approval） | **审批人选择器**（组织架构树选部门 / 搜索选人 / 角色多选 / 动态项"发起人上级"、"来自变量"）、策略 any / all / quorum、标题 / 摘要模板、附件引用、表单 Schema 编辑、超时与超时策略、提醒通道（来自通知通道配置） | `AssigneePicker`（接 `/identity/*`） |
| 循环（foreach） | `items` 变量选择器（只列数组类型字段）、别名、并发、maxItems、batchSize、循环体类型切换（单任务：选节点类型并配置输入，输入映射作用域含 `{{item}}`；子流程：选流程与版本策略）、逐项失败策略、结果收集字段多选（来自循环体输出 Schema） | `ForEachEditor` |
| 重试 / 超时 | `maximumAttempts` / `initialInterval` / `backoffCoefficient` / `maximumInterval` / 不重试错误类型；`startToClose` / `scheduleToClose` / `heartbeat`；显示 NodeSpec 默认值与 `maxAllowedAttempts` 上限 | 表单（Duration 输入组件） |
| 失败处理 | `onError.action`：暂停等人工 / 直接失败 / 跳过（填默认输出）/ 走错误分支（自动新增 `error` handle） | 表单 |
| JSON | 当前节点 JSON 只读 | Monaco |

## 7. 校验与保存

- 编辑时 300ms 防抖跑 `dag-core-ts.validate(dag, nodeTypes)`；问题在底部抽屉列出并在节点上打红/黄角标。
- `保存` → `PUT /flows/{id}/draft`；后端二次校验，返回 `issues`（后端可能有前端无法判断的项，如节点类型下线）。
- `发布` 要求无 error；弹窗填写版本说明；成功后顶栏显示 `v4 · 已发布`，画布变只读，"新建草稿"按钮基于当前版本复制。
- `JSON` 抽屉支持复制 / 下载 / 粘贴导入（导入时校验 `schemaVersion` 并迁移）。
- 自动保存草稿到 `localStorage`（防丢失），进入编辑器时提示恢复。

## 8. 运行监控面板（`/runs/:runId`）

```
┌───────────────────────────────────────────────┬────────────────────────────────┐
│ 只读画布（节点按状态着色，边高亮已执行路径）      │ 运行概览：状态 · 版本 · 触发人 · 耗时│
│  ● 灰 pending  ● 蓝 running(脉冲)  ● 绿 succeeded │ 输入参数（折叠）               │
│  ● 红 failed  ● 橙 paused  ● 紫 waiting_approval │────────────────────────────────│
│  ● 灰斜纹 skipped                               │ 节点详情（点击节点）：           │
│                                                │  状态 / 尝试次数 / 开始-结束 / 耗时│
│                                                │  [输入] [输出] [日志] [错误]      │
│                                                │  操作：重试 · 跳过 · 终止 · 断点  │
│                                                │  审批：通过 / 驳回 + 表单        │
├───────────────────────────────────────────────┴────────────────────────────────┤
│ 实时日志流（按节点过滤、级别过滤、自动滚动、导出）  时间线（节点甘特图）              │
└────────────────────────────────────────────────────────────────────────────────┘
```

- 数据源：进入页面先 `GET /runs/{id}`（快照：节点状态、上下文摘要）+ `GET /runs/{id}/events?limit=500`，然后 `EventSource('/runs/{id}/events/stream?since=<lastEventId>')`；断线重连自动带 `since`。
- 输入 / 输出查看：预览字段内联；完整内容点击加载 `GET /runs/{id}/nodes/{nodeId}/io`，artifact 引用渲染为可下载 / 预览（JSON 表格、xlsx 下载，MinIO 预签名 URL）。
- `foreach` 节点：进度环 + item 表格（状态 / 耗时 / 输出摘要 / 错误），支持按状态筛选、单 item 下钻到子运行监控页。
- 操作按钮调用 `POST /runs/{id}/nodes/{nodeId}/actions`（retry / skip / abort / resume）、`POST /runs/{id}/approvals/{nodeId}`、`POST /runs/{id}/breakpoints`；按钮状态由节点状态驱动（只有 `paused` / `failed` 显示重试等）。
- 时间线：基于 `node.started/succeeded/failed` 事件绘制甘特图，直观看出耗时瓶颈。

## 9. 版本管理页

- 列表：版本号、状态（草稿 / 已发布 / 当前 / 已归档）、发布人、时间、说明、运行次数。
- Diff：两版本 DAG JSON 的结构化对比（节点新增 / 删除 / 修改，边变化，规则变化高亮）；画布并排预览。
- 操作：`发布草稿`、`回滚到此版本`（= 以该版本内容创建并发布新版本，保留历史线性）、`基于此版本新建草稿`、`归档`。
- 运行绑定：运行列表显示所属版本，回滚后新运行走新版本，进行中的运行不受影响（页面明确提示）。

## 10. 业务人员使用路径（阶段 2 验收）

1. 打开"采购月度对账" → 新建草稿。
2. 点击"是否大额差异"分支 → 规则构建器把阈值从 `{{input.threshold}}` 改为常量 `50000`，或新增 case "供应商 A 全部人工确认"（`input.supplier_id eq "SUP-A"`）并连线到审批节点。
3. 校验通过 → 保存 → 发布（填写说明）。
4. 运行一次 → 监控面板确认走向。
5. 效果不对 → 版本页一键回滚。
全过程无后端改动、无重启。

## 11. 工程实践

- 目录：`src/{app,pages,features/{editor,run-monitor,versions,registry,metrics},components/nodes,components/edges,lib/dag-core,api,store}`。
- 类型：`packages/contracts` 由 `schemas/*.json` 生成 TS 类型（`json-schema-to-typescript`），前后端同源。
- 测试：`dag-core-ts` 单测 + 共享规则测试向量；节点组件 Storybook；Playwright 覆盖"拖拽 → 连线 → 保存 → 运行 → 审批"主路径。
- 性能：`nodes/edges` 用 `useShallow` 选择器；> 200 节点开启 `onlyRenderVisibleElements`；日志流虚拟列表（`react-virtuoso`）。
