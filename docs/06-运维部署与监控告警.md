# 运维部署与监控告警（开发环境）

> 目标：`make up` 一键拉起 Temporal 开发集群 + PostgreSQL + Redis + MinIO + Keycloak + 平台服务 + 监控告警；给出维护、备份、升级与生产迁移路径。

---

### 1.1 Temporal 关键配置

- Namespace：`agent-platform`，retention **7d**（开发）；生产建议 30d 并开启归档。
- `dynamicconfig/development.yaml`：
  - `limit.maxIDLength: 255`
  - `frontend.enableUpdateWorkflowExecution: true`（Update 能力）
  - `system.enableEagerWorkflowStart: true`
  - `history.defaultActivityRetryPolicy` 保持默认（业务重试由 DAG 控制）
  - `frontend.workerVersioningDataAPIs`/`WorkflowAPIs`: true（预留 Worker Versioning）
- Search Attributes：`FlowKey (Keyword)`、`FlowVersion (Int)`、`TriggeredBy (Keyword)`、`ParentRunId (Keyword)`。
- Worker 端（Java `WorkerOptions`）：`maxConcurrentActivityExecutionSize`（recon 默认 20）、`maxConcurrentWorkflowTaskExecutionSize` 50、sticky 缓存 `WorkerFactoryOptions.workflowCacheSize` 600；Python `llm-worker` `max_concurrent_activities=5`。

### 1.2 PostgreSQL

- 开发期：单实例，`shared_buffers=512MB`，`max_connections=200`；多库分离便于日后拆机。
- 备份：`make backup` → `pg_dump` 各库到 `backups/<date>/`；Temporal 升级前必备份。
- `platform` 库迁移由 **Flyway** 管理；`temporal` 库 schema 由 `auto-setup` 初始化，升级用 `temporal-sql-tool update-schema`。
- 大表治理：`run_events` 按月分区，保留 30 天；`run_node_items` 随 run 归档。

### 1.3 MinIO（决策 5）

- Bucket：`agent-artifacts`（节点输出、报告，生命周期默认 90 天）、`agent-uploads`（对账单文件上传，30 天）。
- 访问：Worker / API 使用服务账号（`credential_ref=minio-service`）；前端只拿预签名 URL。
- 开发单节点；生产换云对象存储（S3 / OSS / COS）只改 `artifact_store` profile。
- 备份：`mc mirror` 到备份桶；监控 `minio_cluster_capacity_usable_free_bytes`。

### 1.4 Keycloak（决策 4）

- realm `agent-platform`：客户端 `web`（public, PKCE）、`platform-api`（bearer-only）；组 `platform-admin` / `platform-editor` / `platform-operator` / `recon_ops` / `finance_ap` → `role_mappings`。
- 演示用户：`alice`（editor+recon_ops）、`bob`（operator, finance_ap 主管）、`admin`。
- 生产：Keycloak 作为 Broker 接入企业微信 / AD / 现有 OIDC；组织架构同步走 `IdentityProvider` SPI（企业微信通讯录 API / LDAP / SCIM）。

## 2. 监控指标

### 2.1 Temporal Server（`temporal:8000/metrics`，官方 Grafana 看板）

| 指标 | 关注点 |
|---|---|
| `service_requests` / `service_errors` | Frontend 请求错误率 |
| `persistence_latency` | PG 持久层延迟（P95 > 200ms 告警） |
| `workflow_task_schedule_to_start_latency` | **Worker 不足 / 掉线**信号 |
| `activity_schedule_to_start_latency` | 节点队列积压（按 task queue） |
| `workflow_failed` / `workflow_timeout` / `activity_task_error` | 失败趋势 |
| `history_size` / `history_count` | History 膨胀（坑 3 的量化监控） |

### 2.2 SDK / Worker（`:9464/metrics`）

| 指标 | 关注点 |
|---|---|
| `temporal_workflow_task_replay_latency` | 回放耗时（解释器复杂度） |
| `temporal_workflow_task_execution_failed` | **非确定性错误**（`NonDeterminismError`）→ 立即 P1 告警 |
| `temporal_activity_execution_failed{activity_type}` | 节点失败 |
| `temporal_activity_execution_latency{activity_type}` | 节点耗时 |
| `temporal_worker_task_slots_available` | Worker 饱和 |
| `temporal_sticky_cache_hit/miss` | 缓存效率 |

JVM（Micrometer `jvm_*`、`hikaricp_*`、`http_server_requests_*`）指标由 Spring Boot Actuator 暴露，Python `llm-worker` 用 `temporalio` Prometheus runtime。

## 3. 告警规则（Prometheus `alerts/*.yml` + 事件驱动）

| 告警 | 条件 | 级别 | 通道（按路由，默认企业微信） |
|---|---|---|---|
| `TemporalDown` | `up{job="temporal"} == 0` 1m | P1 | 运维群 + 电话（生产） |
| `NonDeterminismDetected` | `increase(temporal_workflow_task_execution_failed{failure_reason=~".*NonDeterminism.*"}[5m]) > 0` | P1 | 运维群 |
| `WorkerOffline` | `platform_worker_online{task_queue} == 0` 2m 或 `workflow_task_schedule_to_start_latency` P95 > 10s 5m | P1 | 运维群 |
| `ActivityBacklog` | `activity_schedule_to_start_latency` P95 > 60s 5m | P2 | 运维群 |
| `NodeFailureRateHigh` | 某 `node_type` 15m 失败率 > 20% 且样本 ≥ 5 | P2 | 业务群（按 flow_key 路由） |
| `NodeFailedPaused`（事件驱动） | projector 收到 `node.failed` 且 `onError=pause` | P2 | 业务群 / 运营（带运行链接、节点、错误摘要、"去处理"按钮） |
| `ApprovalOverdue`（事件驱动） | `approval.reminder` / 待审批超过 `timeout` 的 50% | P3 | 审批人（应用消息） |
| `ApprovalNoAssignee`（事件驱动） | 审批人解析为空 | P2 | 兜底角色 + 运维群 |
| `ForeachItemFailures`（事件驱动） | `foreach.finished` 且 failed / total > 20% | P3 | 业务群 |
| `RunContextLarge` | `platform_run_context_bytes` > softLimit | P3 | 运维群 |
| `PersistenceSlow` | `persistence_latency` P95 > 200ms 5m | P2 | 运维群 |
| `PostgresDiskHigh` / `RedisMemoryHigh` / `MinioCapacityLow` | 使用率 > 80% | P2 | 运维群 |
| `NotificationFailing` | `platform_notification_sent_total{status="failed"}` 15m > 5 | P2 | 备用通道（邮件） |
| `IdentitySyncStale` | 同步超过 6h 未成功 | P3 | 运维群 |
| `LLMCostSpike` | 1h 成本 > 阈值 | P3 | 业务群 |

- Prometheus 告警 → Alertmanager → `platform-api /notifications/alertmanager-webhook` → **通知中心按 `notification_routes` 路由到已配置通道**（默认企业微信，可换钉钉 / 飞书 / 邮件 / Webhook；决策 3）。运维告警与业务通知共用模板体系，消息都带可点击运行 / 看板链接。
- 事件驱动告警由 projector 直接进通知中心，格式一致。
- 抑制与聚合：同一 `flow_key + node_id` 5 分钟内合并；维护窗口静默；`NotificationFailing` 强制走备用通道避免"告警系统自己挂了没人知道"。

## 4. Grafana 看板

1. **Temporal Server**（官方 `server-general`、`server-persistence`）。
2. **Temporal SDK**（官方 `sdk-general`：Worker slots、任务延迟、失败）。
3. **Agent Platform 总览**：运行数 / 成功率 / 进行中 / 待审批 / P95 耗时 / 最近失败列表（点击跳监控页）。
4. **流程明细**（变量 `flow_key`）：节点耗时热力图、失败率、重试率、分支命中分布、审批时长。
5. **LLM 用量**：token、成本、延迟按 profile / node_type。
6. **基础设施**：PG、Redis、MinIO、JVM、容器资源。
7. **通知与审批**：通道发送成功率、审批积压、审批时长分布。

## 5. 日常维护 Runbook

| 场景 | 操作 |
|---|---|
| Worker 升级 | 滚动重启（多副本）；解释器逻辑变更必须带 `Workflow.getVersion`；先 `make test-arch && make test-replay` |
| Temporal 升级 | 备份 PG → 按官方顺序升 schema（`temporal-sql-tool`）→ 升镜像；单跳一个 minor |
| 清理运行数据 | `run_events` 分区 drop；MinIO 生命周期自动过期 + `artifacts` 元数据清理任务；Temporal retention 自动 |
| 卡住的运行 | Temporal UI 查看等待的 Signal / Activity；用 `POST /runs/{id}/nodes/{n}/actions` 处置；极端情况 `temporal workflow reset` 到指定事件 |
| 非确定性告警 | 立即回滚 Worker 镜像；用 History 回放定位；修复后加 `getVersion` 分支重新发布 |
| 密钥轮换 | `credentials` 表 / Vault 更新；DAG 与 profile 只含 `credential_ref`，无需改流程 |
| 通知通道故障 | `POST /notifications/channels/{name}/test` 诊断；临时切换 `is_default` 到备用通道 |
| 组织架构变更 | `POST /identity/sync`；审批人快照不回溯（进行中审批可用 `transfer` 转办） |
| 新企业接入 | 配置 ERP `document_source` profile（三选一或多个）→ `test` 预览映射 → 配置通知通道 → 配置身份源 → 导入流程模板 |

## 6. 安全基线（开发环境即执行）

- Temporal gRPC 仅内网；Temporal UI / MinIO Console / Grafana 走反向代理 + OIDC。
- platform-api：OIDC JWT（内部）+ API Key（开放）；CORS 白名单。
- 密钥不进 DAG、不进日志（SDK 脱敏）、不进 profile 明文（`credential_ref`）；`.env` 不入库。
- 直连 ERP 库只用只读账号；`sql_query` 节点白名单 + 行数上限。
- 容器只读根文件系统、非 root 运行；MinIO bucket 私有，仅预签名访问。

## 7. 生产迁移路径（不在阶段 1/2 范围，提前留口）

| 项 | 开发 | 生产 |
|---|---|---|
| Temporal | auto-setup 单容器 | 官方 Helm：frontend/history/matching/worker 各 ≥ 2 副本；PG 主从或云 RDS；可见性可用 PG（≤ 数百万 workflow）或 Elasticsearch |
| 平台 DB | 单 PG | 云 RDS + 读副本；`run_events` 可迁 ClickHouse |
| 事件总线 | Redis 单机 | Redis Sentinel/Cluster 或 Kafka |
| Artifact | MinIO 单节点 | MinIO 分布式 / 云对象存储（S3 / OSS / COS），改 profile 即可 |
| 身份 | Keycloak 单容器 | Keycloak HA 或企业 IdP 直连；组织架构同步走企业微信通讯录 / AD |
| Worker | compose 副本 | K8s Deployment + HPA（按 `task_slots_available` / 队列延迟）；业务节点随 AI 采购 / 销售服务部署 |
| 部署 | compose | Helm + ArgoCD；镜像 SBOM 扫描 |
| 告警 | 企业微信（可配） | 多通道路由 + 电话值班（P1） |
